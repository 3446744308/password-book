## 1. 规范适用范围与总则

1. 本规范适用于密码本项目的**全部代码与配置**：`server/`、`web/`、`scripts/`、未来 `app/`。
2. 冲突时的优先级：**安全规范（第 6 章）> API 规范（第 4 章）> 其他章节 > 个人习惯**。
3. 无法避免要偏离规范时：在 PR 描述中写明"偏离条款 + 理由"，经确认后合并。
4. 规范本身通过 `docs/` 版本管理演进，修订需更新第 9 章修订记录。

## 2. 技术栈与版本管理

| 类别 | 约束 |
| --- | --- |
| 运行时 | Node.js ≥ 18，团队统一使用 LTS 版本 |
| 前端 | React 18 + Ant Design 5 + Vite 5 + TypeScript 5（**前端必须 TS**） |
| 后端 | Express 4 + JavaScript（ESM，`"type": "module"`）；后期可平滑迁移到 TS |
| 依赖原则 | 能用内置模块不引第三方（加密、文件、随机数一律内置）；引第三方需在 PR 说明理由 |
| 版本锁定 | `package.json` 用 `^` 锁主版本；提交 `package-lock.json`；升级主版本需单独 PR |
| 禁止引入 | 任何原生编译依赖（node-gyp 类）、已停止维护的包、与现有功能重复的工具库 |

## 3. 仓库与目录规范

### 3.1 顶层布局

```
密码本/
├─ docs/        # 全部项目文档（Markdown，编号前缀）
├─ server/      # 后端（独立 package.json）
├─ web/         # 前端（独立 package.json）
├─ app/         # 未来手机 App（预留，不在 V1.0）
├─ scripts/     # 运维/一次性脚本（备份、扫描明文、初始化）
├─ data/        # 运行时数据（★ 永不提交 git）
└─ README.md    # 快速开始
```

### 3.2 强制约定

1. **`data/` 目录内容禁止提交 git**（含备份、日志）。`.gitignore` 必须包含 `data/`、`!data/.gitkeep`、`backups/`、`.env`。
2. `data/` 只允许 `server/src/storage/`（及迁移脚本）读写，其他模块禁止直接 `fs` 访问数据文件。
3. 新增文档一律放 `docs/`，命名 `NN-中文标题.md`（两位数字编号，便于排序）。
4. 代码文件名：后端小写短横线或小写驼峰均可，但**同一目录内统一**；前端组件文件**PascalCase**（`EntryTable.tsx`），非组件工具文件 camelCase。
5. 禁止提交：编译产物（`dist/`、`build/`）、IDE 私有配置、`node_modules/`、任何密钥与 `.env` 实体文件。

## 4. API 设计规范（多端统一，最高约束）

> 完整端点清单见 [03-API接口文档](./03-API接口文档.md)。本章是**所有端点必须遵守的通用规则**，未来手机 App 直接复用。

### 4.1 URL 与版本

1. 一切接口前缀 `/api/v1`；破坏性变更（字段删除/语义变化）必须升版本 `/api/v2`，旧版本保留至少一个大版本周期。
2. 资源用**名词复数**、全小写、短横线连接：`/api/v1/entries`、`/api/v1/categories`。
3. 操作用 **HTTP 动词表达**，禁止把动词写进路径（除少数 RPC 式例外，见 4.3）。

| 动词 | 语义 | 成功码 |
| --- | --- | --- |
| GET | 查询，幂等，无副作用 | 200 |
| POST | 创建 / 触发动作 | 201（创建）/ 200（动作） |
| PUT | 全量替换 | 200 |
| PATCH | 局部更新 | 200 |
| DELETE | 删除 | 204（无响应体） |

4. 查询参数用小驼峰：`?keyword=xx&page=1&size=20`。
5. URL 长度限制 2KB；搜索关键词超长直接 400。

### 4.2 请求与响应信封

**成功响应**（2xx，直接返回资源或资源集合）：

```json
{ "data": { "...": "资源对象或数组" } }
```

分页时额外带：

```json
{ "data": [], "pagination": { "page": 1, "size": 20, "total": 135 } }
```

**错误响应**（4xx/5xx，结构固定）：

```json
{ "error": { "code": "AUTH_INVALID_CREDENTIALS", "message": "主密码不正确", "details": [] } }
```

规则：

1. `code` 为**稳定机器码**（全大写下划线），一旦发布不得修改含义；`message` 为人类可读文案，**可本地化，前端不得解析 message 做逻辑**。
2. 字段命名全小驼峰；时间一律 **ISO 8601 UTC** 字符串（`2026-11-16T09:00:00.000Z`）；ID 一律字符串（ULID）。
3. 布尔字段用 `true/false`，禁止 `0/1` 或 `"yes"`。
4. 金额/数量不涉及；可选字段**省略而非传 null**（除非语义需要显式清空，此时用 `null`）。
5. 任何响应**不得**包含：主密码、KEK、DEK、JWT 密钥、密码明文（除专门的 reveal 端点）。

### 4.3 例外：动作型端点

无法用资源语义表达的动作，允许 `POST /api/v1/<资源>/<动作>`：

```
POST /api/v1/auth/login        POST /api/v1/auth/refresh
POST /api/v1/entries/:id/favorite   POST /api/v1/categories/:id/transfer
```

约束：动作用**动词原形**、仅一层、必须 POST、必须幂等可重放或带防重 token。

### 4.4 鉴权与安全（通用）

1. 除 `POST /auth/setup`、`POST /auth/login`、`GET /system/health` 外，一律要求 `Authorization: Bearer <accessToken>`，缺失/过期 → `401 TOKEN_MISSING` / `401 TOKEN_EXPIRED`。
2. Token 通过 `Set-Cookie` 下发时必须：`HttpOnly; Secure; SameSite=Strict; Path=/`；JS 只读不写。
3. 所有写接口服务端**必须重新校验**输入（不信任前端），校验失败 → `400 VALIDATION_ERROR` + `details`。
4. 敏感端点（auth、master 相关）默认由「连续失败锁定」保护；如需按 IP 限速，用
   `RATE_LIMIT_ENABLED=true` 打开限速中间件（默认关闭，见 docs/03 §1.6）。
5. 跨域：生产白名单Origin，禁止 `*`；开发期允许 localhost:5173。

### 4.5 状态码约定

| 码 | 场景 |
| --- | --- |
| 200/201/204 | 见 4.1 |
| 400 | 参数校验失败 `VALIDATION_ERROR` |
| 401 | 未认证/凭证错误/TOKEN 过期 |
| 403 | 已认证但无权限 |
| 404 | 资源不存在 `NOT_FOUND` |
| 409 | 冲突（重名等）`CONFLICT` |
| 423 | 主密码锁定中 `LOCKED_OUT` |
| 429 | 触发限速 `RATE_LIMITED`（带 `Retry-After` 头；仅在启用限速时出现） |
| 500 | 未知服务端错误 `INTERNAL_ERROR`（不回传堆栈） |
| 503 | 存储不可用/迁移中 `SERVICE_UNAVAILABLE` |

### 4.6 文档同步（强制）

1. `docs/03-API接口文档.md` 是**唯一权威源**；新增/修改端点必须在**同一个 PR** 内更新该文档，否则不予合并。
2. 字段增删同步更新数据字典章节。
3. App 端开发仅依据 API 文档，**禁止**直接阅读后端源码倒推接口。

## 5. 命名规范

### 5.1 通用

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 变量/函数 | 小驼峰，名词性命名避免缩写（除业界通用） | `masterPassword`、`deriveKek()` |
| 类型/组件/类 | 大驼峰 | `EntryTable`、`CryptoService` |
| 常量 | 全大写下划线 | `MAX_RETRY`、`SCHEMA_VERSION` |
| 布尔变量 | `is/has/should/can` 前缀 | `isLocked`、`hasHistory` |
| 事件/事件名 | 全大写下划线（审计日志事件） | `LOGIN_FAIL`、`ENTRY_DELETE` |

### 5.2 后端

- 路由文件：`entries.js`（资源名复数）。
- Service：`entryService.js`，导出 `createEntry/updateEntry/...`。
- 数据库字段（JSON 键）：**小驼峰** `categoryId`、`passwordEnc`、`createdAt`。
- 错误码：`AUTH_INVALID_CREDENTIALS`（全大写下划线）。
- 中间件：`auth.js`、`rateLimit.js`、`errorHandler.js`。

### 5.3 前端

- React 组件：PascalCase 文件 + PascalCase 组件；页面放 `pages/`，复用件放 `components/`。
- Hook：`useXxx`；Store：`useXxxStore`；样式类：`entry-table__row`（BEM 简化式）。
- CSS 变量/主题 token 走 Ant Design `theme.token`，禁止散落硬编码色值。

### 5.4 数据字段命名统一表（前后端/App 共同遵守）

| 概念 | 字段名 | 禁止写法 |
| --- | --- | --- |
| 分类 ID | `categoryId` | `cat_id`、`folderId` |
| 条目 ID | `entryId` / 路径参数 `:id` | `item_id` |
| 密码密文 | `passwordEnc` | `encPassword`、`pwd` |
| 创建/更新时间 | `createdAt` / `updatedAt` | `create_time`、`ctime` |
| 关键词搜索 | `keyword` | `q`、`search`（保留 `q` 给未来全局搜索） |
| 收藏 | `favorite` | `starred`、`is_fav` |

## 6. 安全规范（强制条款，违反即打回）

1. **明文禁令**：任何日志、报错、调试输出、埋点中**禁止**出现主密码、密码明文、KEK、DEK、JWT 签名密钥。Code Review 必查。
2. **加密唯一入口**：加解密只经 `server/src/crypto/` 模块，禁止在业务代码里手写 `crypto.createCipheriv`。
3. **文件写入唯一入口**：数据文件只经 `storage/` 的原子写与写队列，禁止散落 `fs.writeFile`。
4. **常量时间比较**：主密码/Token 校验必须用 `crypto.timingSafeEqual`。
5. **输入校验**：所有外部输入（body/query/params/header）服务端白名单校验；ID 字段正则 `^[A-Z0-9]{26}$|^[a-z_][a-z0-9_-]{0,50}$`，并做路径穿越检查。
6. **最小响应**：列表接口不得返回 `passwordEnc`；只有 `GET /entries/:id/reveal` 经鉴权后返回明文，且写审计日志。
7. **密钥不落前端**：前端代码/构建产物中禁止出现任何密钥、JWT secret；`data/` 目录禁止被静态托管。
8. **依赖安全**：禁止引入来源不明包；定期 `npm audit`，高危漏洞 7 天内修复。
9. **HTTPS**：任何远程访问场景必须 HTTPS；开发期 localhost 例外。
10. **前端存储**：Token 若存 localStorage 需评估 XSS 风险并默认短时效；明文密码禁止进 localStorage/sessionStorage/URL/Redux 持久化。
11. **失焦保护**：密码明文展示组件 30 秒自动掩码；窗口失焦即掩码。
12. **备份保护**：`data/backups/` 与 `data/` 同级同策略，禁止上传到任何第三方云同步目录做明文同步。

## 7. Git 工作流

### 7.1 分支模型

```
main            # 生产就绪，保护分支，禁止直接 push，只能 PR + 评审
└─ develop      # 集成分支（可选，单人项目可省略）
   └─ feature/<短描述>   # 功能分支，如 feature/history-versions
   └─ fix/<短描述>       # 缺陷修复
   └─ docs/<短描述>      # 仅文档
```

### 7.2 提交规范（Conventional Commits）

```
<type>(<scope>): <简短描述，中文可>

type ∈ feat | fix | docs | style | refactor | perf | test | chore
scope ∈ server | web | data | api | scripts | docs
```

示例：

```
feat(server): 条目新增接口接入写队列与审计日志
fix(web): 搜索防抖导致的重复请求
docs(api): 新增 favorite 动作端点说明
```

要求：

1. 一次提交只做一件事；禁止"修复若干问题"式提交。
2. 提交前本地必须通过 `npm run lint` 与 `npm test`。
3. 敏感文件（`data/`、`.env`）误提交视为**安全事故**，须立即轮换密钥并清史。

### 7.3 PR / 评审清单

- [ ] 符合第 4 章 API 规范，且 API 文档已同步
- [ ] 无明文密码进日志/响应（第 6 章）
- [ ] 新增/改动字段已更新数据字典
- [ ] 有测试覆盖核心路径，`npm test` 通过
- [ ] 无 `console.log` 调试残留、无注释掉的大段死代码
- [ ] 提交信息符合 Conventional Commits

## 8. 代码风格

### 8.1 格式化与 Lint

| 项 | 工具 | 关键配置 |
| --- | --- | --- |
| 格式化 | Prettier（两端统一） | `printWidth: 100`、`singleQuote: true`、`semi: true`、尾随逗号 `all` |
| 后端 Lint | ESLint（`eslint:recommended` + `import` 插件） | 未使用变量报错（允许 `_` 开头） |
| 前端 Lint | ESLint + `typescript-eslint` + React Hooks 规则 | Hooks 依赖缺失报错 |

统一：2 空格缩进、LF 换行、UTF-8 无 BOM、文件末尾保留换行。**禁止个人 IDE 私有规则**。

实际落地的配置（仓库根，两端共用）：

| 文件 | 作用 |
| --- | --- |
| `.prettierrc.json` | `printWidth: 100`、`singleQuote`、`semi`、`trailingComma: all`、`endOfLine: lf` |
| `.prettierignore` | 排除 `node_modules/`、`dist/`、`coverage/`、`data/`、`package-lock.json`、`*.md`（文档手写排版不参与格式化） |
| `.gitattributes` | `* text=auto eol=lf`，防止 Windows 上 `core.autocrlf` 把检出内容变成 CRLF |
| `server/eslint.config.js`、`web/eslint.config.js` | ESLint **flat config**（不再使用 `.eslintrc`），后端 `eslint:recommended`，前端叠加 `typescript-eslint` + React Hooks |

两端都提供 `npm run format`（写入）与 `npm run format:check`（CI 只校验）。

### 8.2 代码风格细则（后端 JS / 前端 TS 通用）

```js
// ✅ 正确：ESM、const 优先、模板字符串、可选链
import { deriveKek } from '../crypto/kbkdf.js';
const label = entry?.title ?? '未命名';

// ❌ 禁止：var、CommonJS require、字符串拼接 +、== 松散比较
var a = require('fs'); if (a == null) { ... }
```

1. 异步一律 `async/await`，禁止裸 `.then()` 链（需要组合时用 `Promise.all`）。
2. 错误必须 `try/catch` 或交由错误中间件；**禁止空 catch**；禁止吞错误只 `console.log`。
3. 魔法值必须提为命名常量。
4. 单函数 ≤ 50 行；圈复杂度 > 10 拆分。
5. 注释解释"为什么"而非"是什么"；对外导出的函数用 JSDoc/TS doc 注明参数、返回、抛错。
6. 前端禁止内联巨量样式；复用样式进 CSS Module 或主题 token。

### 8.3 错误与日志

1. 业务错误一律 `throw new AppError('CODE', httpStatus, '中文说明')`，由全局中间件统一转响应。
2. 日志格式：结构化 `logger.info(event, { fields })`；级别 use：`error`（需人工介入）、`warn`（可自愈）、`info`（关键业务动作）。
3. 生产环境禁止输出堆栈到响应体，堆栈只进服务端日志。

## 9. 测试规范

### 9.1 覆盖要求

| 模块 | 要求 |
| --- | --- |
| crypto（加解密/KDF/verifier） | 100% 分支覆盖，含篡改密文报错用例 |
| storage（原子写/队列/迁移） | 覆盖并发写、崩溃中断模拟 |
| auth（登录/限速/锁定） | 覆盖正确、错误、超次锁定、Token 过期 |
| entries/categories CRUD | 每端点至少：正常、参数非法、未认证、不存在 4 类用例 |
| 前端 | 纯逻辑（密码生成、格式化、错误文案）必须有单元测试；关键交互组件（SecretField、生成器、自动锁定）必须有组件测试；不强求 E2E |

### 9.2 命名与组织

- 测试文件与源文件同名加 `.test.js/.test.tsx`，放 `test/` 或同目录。
- 用例命名中文可接受：`it('主密码错误 5 次后应返回 423')`。
- 测试必须**自建临时 `data/` 目录**（`os.tmpdir()`），跑完删除，禁止写真实 `data/`。
- 断言禁止只断"不抛错"，必须断言关键字段值。

### 9.3 命令约定

```bash
npm run lint      # 两端都必须提供
npm run test      # 单元/接口测试
npm run build     # 前端生产构建（类型检查 + 打包）
```

前端用 **Vitest + jsdom + @testing-library/react**（配置见 `web/vitest.config.ts`，setup 补齐
jsdom 缺失的 `matchMedia`/`ResizeObserver` 并显式 `cleanup`）：

- 纯逻辑（`src/utils/**`）直接单元测试；
- 关键交互组件（`SecretField`、密码生成器、空闲自动锁定）用组件测试覆盖渲染、鉴权交互与定时行为；
- 测试文件也纳入类型检查：`npm run typecheck` 会分别跑 `tsconfig.json`（src）与
  `tsconfig.test.json`（test + vitest 配置），避免测试代码里的语法/类型错误只有在运行时才暴露。

CI（可选 GitHub Actions）顺序：`install → lint → format:check → typecheck → test → build`，任一失败即红。

## 10. 文档规范

1. 全部 Markdown，存放 `docs/`，文件名 `NN-主题.md` 两位编号。
2. 文档头部含表格：版本、日期、状态（草稿/待评审/已发布）、关联文档。
3. 图表统一 Mermaid；代码块必须标语言。
4. 界面截图用 `docs/images/<模块>/` 相对路径引用，禁止外链。
5. 每份文档结尾必须有**修订记录表**。
6. 术语首次出现给出中英文对照与一句话解释（参照设计文档附录 12.1）。
7. 面向 App 开发者的接口说明只写在 `03-API接口文档.md`，其他文档如需引用一律链接过去，不复制粘贴（避免两处不一致）。

## 11. 环境、配置与数据管理

### 11.1 环境变量

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `PORT` | 后端端口 | `3100` |
| `HOST` | 监听地址；**保持回环地址**，`dev` 模式下绑到非回环会触发安全告警 | `127.0.0.1` |
| `DATA_DIR` | 数据目录绝对/相对路径 | `./data` |
| `AUTH_MODE` | `dev` \| `strict`（DEK 落盘策略，见设计文档 4.5） | `dev` |
| `JWT_SECRET_FILE` | JWT 密钥文件路径 | `./data/jwt.secret` |
| `LOG_LEVEL` | `debug` \| `info` \| `warn` \| `error` | `info` |
| `LOG_TO_FILE` | 是否把结构化日志落盘（默认 `true`） | `true` |
| `LOG_RETENTION_DAYS` | 日志文件保留天数（默认 14） | `14` |
| `ACCESS_TOKEN_TTL` | 会话时长**初值**（秒）；仅在 `config.json` 尚无 `lockMinutes` 时生效，之后以配置为准 | `1800` |

规则：

1. `.env` **禁止提交**，只提交 `.env.example`（含注释与占位值）。
2. 配置读取集中在 `server/src/config.js`，业务代码禁止 `process.env` 散落读取。
3. 敏感配置（密钥）优先"文件路径型变量"而非值型变量，避免被进程列表读取。

### 11.2 数据（`data/`）管理

1. **只增不改结构**：任何文件结构变更必须走 `schemaVersion` 迁移流程（见设计文档 4.9）。
2. 禁止手工编辑 `data/` 下文件；需修改数据走 API 或维护脚本（`scripts/`）。
   合规性检查用 `npm --prefix server run scan`（明文扫描，见 §12 自检清单）。
3. 备份策略：改动加密/迁移逻辑前**必须**先执行 `npm run backup`。
4. 数据文件内敏感字段只有 `passwordEnc`、`notesEnc`；若引入新敏感字段，必须先评审加密方式再写码。

### 11.3 日志

- 开发与生产统一输出**单行 JSON**（可被容器/日志采集直接消费），同时追加到
  `data/logs/app-YYYYMMDD.log`；由 `LOG_TO_FILE=false` 可关闭文件输出（只读介质或测试）。
- 日志文件按天轮转，保留 14 天（`LOG_RETENTION_DAYS`），超期在启动时清理；
  `audit.jsonl` 保留 1000 条（设计文档 6.3）。两者职责不同：app 日志用于排障，audit 用于安全审计。
- 日志中 IP 可记录，用户名/标题可记录，**字段名含 `pass/secret/token/dek/kek/verifier/authorization`
  的一律自动脱敏为 `[REDACTED]`**（`logger.js` 内置兜底，不依赖调用方自觉）。
